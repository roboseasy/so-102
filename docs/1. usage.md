# SO-102 LeRobot 플러그인 사용법

먼저 **LeRobot v0.6.0을 설치**하고, 이어서 **로보시지 SO-102 플러그인**을 추가한다. 이후 보정과 제어에는 기존 `lerobot-calibrate`, `lerobot-teleoperate` 명령을 사용한다.

## 1. 처음부터 설치하기

[위키독스 설치 안내](https://wikidocs.net/385990)의 Conda 흐름을 따라 진행한다. 아래 명령은 **Ubuntu의 bash 터미널** 기준이며, 환경 이름은 **`lerobot060`**, Python은 **3.12**로 통일한다.

**설치 대상은 이 PC의 `lerobot060` 가상환경이다.** LeRobot과 SO-102의 소스 코드는 각각 아래 폴더에 두고, 같은 가상환경에서 사용할 수 있도록 설치한다.

| 구분 | 위치 또는 이름 | 역할 |
|---|---|---|
| 실행 환경 | Conda 환경 `lerobot060` | Python 3.12와 설치한 라이브러리를 사용한다. |
| LeRobot 소스 | `~/lerobot` | Hugging Face LeRobot v0.6.0 코드다. |
| SO-102 소스 | `~/workspace/so-102` | LeRobot에 7축 SO-102를 추가하는 이 프로젝트의 코드다. |

`~`는 현재 사용자의 홈 폴더다. 예를 들어 로그인 계정이 `master`이면 `~/lerobot`은 `/home/master/lerobot`이다.

설치 명령에서 **환경을 선택하는 것**과 **소스 폴더를 선택하는 것**은 다음처럼 구분한다.

| 명령 | 의미 |
|---|---|
| `conda activate lerobot060` | 설치와 실행에 사용할 Python 환경을 선택한다. 현재 폴더는 바뀌지 않는다. |
| `cd ~/lerobot` | 설치할 LeRobot 소스 폴더로 이동한다. |
| `pip install -e .` | 현재 폴더의 Python 프로젝트를 선택한 환경에 Editable 방식으로 설치한다. |

마지막 명령의 **`.`은 현재 폴더**다. `~/lerobot`에서 실행하면 LeRobot을, `~/workspace/so-102`에서 실행하면 SO-102 플러그인을 설치한다. `-e`로 설치한 Python 소스는 원래 폴더에서 계속 사용하므로 설치 후에도 두 소스 폴더를 유지한다. 자세한 동작은 [pip의 Editable 설치 안내](https://pip.pypa.io/en/stable/topics/local-project-installs/#editable-installs)를 참고한다.

처음 설치하는 PC에서는 아래 1.1부터 진행한다. 두 소스가 이미 설치된 PC에서는 1.9에서 환경과 설치 위치를 확인할 수 있다.

### 1.2. Miniconda 설치

Miniconda·Miniforge·Anaconda 중 하나가 이미 설치되어 `conda --version`이 실행되면 이 단계는 건너뛴다.

```bash
cd ~
wget "https://repo.anaconda.com/miniconda/Miniconda3-latest-$(uname)-$(uname -m).sh"
bash "Miniconda3-latest-$(uname)-$(uname -m).sh"
```

설치 화면에서 약관을 확인하고, 동의하면 `yes`를 입력한다. 설치 위치는 기본값 `~/miniconda3`를 사용하고, 마지막 Conda 초기화 질문에도 `yes`를 선택한다. 설치가 끝나면 **터미널을 닫고 새로 연다**.

```bash
conda --version
```

설치 파일 이름에 들어가는 OS와 CPU 아키텍처는 다음 명령으로 확인할 수 있다.

```bash
echo "$(uname)"
echo "$(uname -m)"
```

| 표현 | 의미 | 대표적인 값 |
|---|---|---|
| `$(uname)` | 운영체제 이름 | `Linux`, `Darwin`(macOS) |
| `$(uname -m)` | CPU 아키텍처 | `x86_64`(인텔·AMD), `arm64`(Apple Silicon), `aarch64`(ARM Linux) |

위 다운로드 주소는 해당 조합의 설치 파일을 선택한다. 지원 조합은 [Miniconda 시스템 요구사항](https://www.anaconda.com/docs/getting-started/miniconda/system-requirements)을 따른다. 설치 화면은 [공식 Linux 설치 안내](https://www.anaconda.com/docs/getting-started/miniconda/install/linux-install)를 참고한다.

### 1.5. LeRobot v0.6.0 소스 내려받기

홈 폴더에 **v0.6.0 태그**를 복제한다. `git clone`은 소스 코드를 `~/lerobot`에 내려받는 단계이고, Python 라이브러리 설치는 1.7에서 진행한다.


마지막 명령에서 `v0.6.0`이 표시되어야 한다.

### 1.6. PyTorch 설치

아래 **CPU 또는 NVIDIA GPU 중 한 가지**를 선택한다. Ubuntu `x86_64` 기준 예시이며, 기존에 호환되는 PyTorch가 설치되어 있으면 재설치하지 않아도 된다.

**CPU 사용 — GPU 없이 기본 텔레오퍼레이션**

```bash
pip install torch==2.10.0 torchvision==0.25.0 \
  --index-url https://download.pytorch.org/whl/cpu
```

**NVIDIA GPU 사용 — CUDA 12.8 지원 드라이버가 준비된 PC**

```bash
nvidia-smi
pip install torch==2.10.0 torchvision==0.25.0 \
  --index-url https://download.pytorch.org/whl/cu128
```

위 버전 조합은 [PyTorch 공식 설치 명령](https://pytorch.org/get-started/previous-versions/)과 [LeRobot v0.6.0 의존성 범위](https://github.com/huggingface/lerobot/blob/v0.6.0/pyproject.toml)를 기준으로 한다. macOS·Jetson 등 다른 플랫폼은 해당 플랫폼용 PyTorch 설치 안내를 따른다.

### 1.7. LeRobot을 Editable 모드로 설치

**설치할 코드: `~/lerobot` → 설치 대상 환경: `lerobot060`**

아래 명령을 순서대로 실행한다. `pwd`는 현재 폴더를 확인하는 명령이다.

```bash
conda activate lerobot060
cd ~/lerobot
pwd
pip install -e .
pip install -e ".[core_scripts,feetech]"
python -c "import lerobot; print(lerobot.__version__)"
```

`pwd` 출력은 자신의 홈 폴더 아래 `lerobot`이어야 한다. 첫 번째 `pip install`은 그 폴더의 LeRobot을 설치하고, 두 번째는 공식 로봇 명령과 Feetech 모터 통신에 필요한 의존성을 추가한다. `core_scripts`는 보정·제어·녹화 등 공식 CLI에, `feetech`는 SO-102 모터 통신에 필요하다.

마지막 버전 출력은 `0.6.0`이어야 한다.

### 1.8. 로보시지 SO-102 플러그인 추가

**설치할 코드: `~/workspace/so-102` → 설치 대상 환경: 같은 `lerobot060`**

제품과 함께 받은 **이 프로젝트의 `so-102` 소스 폴더**를 준비한다. 먼저 소스를 둘 상위 폴더를 만든다.

```bash
mkdir -p ~/workspace
```

파일 관리자에서 제공받은 `so-102` 폴더를 `~/workspace` 안에 복사한다. 이미 `~/workspace/so-102`에 이 프로젝트가 있으면 복사 단계를 건너뛴다. 폴더 안에는 다음 파일과 디렉터리가 있어야 한다.

```text
~/workspace/so-102/
├── pyproject.toml
└── src/
    ├── lerobot_robot_so102/
    └── roboseasy_so102/
```

이제 **SO-102 폴더로 이동한 뒤** 설치한다.

```bash
conda activate lerobot060
cd ~/workspace/so-102
pwd
ls pyproject.toml
pip install -e .
```

`pwd`는 자신의 홈 폴더 아래 `workspace/so-102`를, `ls`는 `pyproject.toml`을 표시해야 한다. `pip install -e .`는 이 파일에 정의된 **`lerobot_robot_so102` 플러그인**을 설치한다. 설치하면 기존 LeRobot 명령에서 `so102_follower`와 `so102_leader`를 사용할 수 있다.

### 1.9. 설치 결과 확인

```bash
conda activate lerobot060
python -c "import sys; print(sys.executable)"
python -c "import lerobot; print(lerobot.__version__)"
pip show lerobot lerobot_robot_so102
pip check
```

위 명령은 현재 환경의 Python과 라이브러리 설치 상태를 확인한다. 아래 표의 소스 위치는 1.5~1.8의 Editable 설치 기준이다.

| 확인 항목 | 기대하는 결과 |
|---|---|
| Python 실행 파일 | 경로에 `envs/lerobot060/bin/python`이 포함된다. |
| LeRobot 버전 | `0.6.0` |
| `pip show`의 `lerobot` 항목 | `Editable project location`이 자신의 `~/lerobot`을 가리킨다. |
| `pip show`의 `lerobot_robot_so102` 항목 | `Editable project location`이 자신의 `~/workspace/so-102`를 가리킨다. |
| `pip check` | 의존성 문제가 없으면 `No broken requirements found.`가 출력된다. |

`pip show`의 `Location`은 가상환경 안의 설치 위치이고, `Editable project location`은 실제 소스 폴더다. PyPI 방식으로 설치한 LeRobot에는 `Editable project location`이 표시되지 않는다. 위 두 설치에서 같은 가상환경을 사용했는지 확인한 뒤 **2번 자동 발견 확인**으로 진행한다.

### 1.10. 선택 기능 추가 설치

**기본 텔레오퍼레이션 설치는 1.9까지면 된다.** 아래는 학습·시뮬레이션 등을 추가할 때 사용하는 예시다. 필요한 명령만 선택한다.

추가 기능도 **LeRobot 폴더**에서 설치한다.

```bash
conda activate lerobot060
cd ~/lerobot
```

**정책 학습**

```bash
pip install -e ".[training]"
```

**정책별 의존성 — 사용할 정책 선택**

```bash
pip install -e ".[training,smolvla]"
pip install -e ".[training,pi]"
pip install -e ".[training,groot]"
pip install -e ".[training,xvla]"
```

**시뮬레이션 — 사용할 환경 선택**

```bash
pip install -e ".[aloha]"
pip install -e ".[pusht]"
```

**다른 모터 플랫폼을 함께 사용하는 경우**

```bash
pip install -e ".[dynamixel]"
```

여러 기능은 쉼표로 조합한다. 전체 기능이 필요한 개발 환경에서는 `all`을 선택할 수 있다.

```bash
pip install -e ".[core_scripts,feetech,training,smolvla]"
# 전체 기능을 설치할 때만 선택
pip install -e ".[all]"
```

추가 기능의 전체 목록은 [LeRobot v0.6.0의 pyproject.toml](https://github.com/huggingface/lerobot/blob/v0.6.0/pyproject.toml)을 참고한다. 이 명령은 의존성을 추가하며, SO-102의 녹화·학습 실장비 검증을 의미하지는 않는다.

<details>
<summary>선택: 소스 복제 대신 PyPI에서 LeRobot v0.6.0 설치</summary>

LeRobot 소스를 수정할 필요가 없다면 **1.5와 1.7 대신** 다음 명령을 사용할 수 있다. Conda·FFmpeg·PyTorch 준비와 **1.8의 SO-102 플러그인 설치는 동일하게 필요하다**.

```bash
conda activate lerobot060
pip install "lerobot[core_scripts,feetech]==0.6.0"
python -c "import lerobot; print(lerobot.__version__)"
```

PyPI 방식으로 선택 기능을 추가할 때도 버전을 지정한다. 이 경우 1.10의 `pip install -e ...` 대신 아래 형식을 사용한다.

```bash
pip install "lerobot[core_scripts,feetech,training,smolvla]==0.6.0"
```

</details>

## 2. 자동 발견 확인 — 로봇 연결 불필요

```bash
conda activate lerobot060
lerobot-teleoperate --robot.type=so102_follower --teleop.type=so102_leader --help
lerobot-calibrate --robot.type=so102_follower --help
```

`so102_follower`, `so102_leader`와 공식 SO 장치 옵션이 도움말에 표시되어야 한다. 사용자가 Python import를 추가하거나 LeRobot 내부 파일을 수정할 필요는 없다.

## 3. 포트 고정

[USB 포트 고정 안내](<2. ports.md>)에 따라 다음 별칭을 먼저 만든다.

| 역할 | 권장 별칭 | 현재 확인 포트 |
|---|---|---|
| 리더 | `/dev/so102_leader` | `/dev/ttyACM0` |
| 팔로워 | `/dev/so102_follower` | `/dev/ttyACM1` |

별칭은 플러그인 설치가 아닌 장치별 udev 규칙으로 만든다. 별칭이 없으면 명령의 포트 옵션에 실제 장치 경로를 사용한다.

## 4. LeRobot 기본 캘리브레이션

암을 고정하고 토크가 풀려도 떨어지지 않도록 지지한다. 다음 명령을 각각 실행해 화면 안내를 따른다.

```bash
lerobot-calibrate \
  --teleop.type=so102_leader \
  --teleop.port=/dev/so102_leader \
  --teleop.id=so102_leader

lerobot-calibrate \
  --robot.type=so102_follower \
  --robot.port=/dev/so102_follower \
  --robot.id=so102_follower
```

공식 SO-100/101과 동일하게 중앙 자세에서 오프셋을 맞춘 뒤 `wrist_roll`을 제외한 관절을 안내에 따라 움직인다. SO-102의 추가 축인 `wrist_yaw`도 측정한다. 기록을 마치면 Enter를 누른다. `wrist_roll`의 보정 범위는 공식 코드와 같이 0~4095로 저장한다.

기존 보정 파일이 있으면 Enter로 적용하거나 `c`를 입력해 다시 측정할 수 있다. 중간에 보정이 실패했다면 일부 모터 레지스터가 바뀌었을 수 있으므로 해당 장치의 전체 보정을 다시 수행한다.

보정 파일은 **LeRobot 기본 JSON 형식**을 사용한다. 기본 경로는 다음과 같다. Hugging Face/LeRobot 캐시 환경 변수를 변경했다면 해당 설정을 따른다.

```text
~/.cache/huggingface/lerobot/calibration/
├── robots/so102_follower/so102_follower.json
└── teleoperators/so102_leader/so102_leader.json
```

별도 저장 위치가 필요하면 각 명령에 `--robot.calibration_dir=...` 또는 `--teleop.calibration_dir=...`를 추가하고 다음 실행에서도 같은 값을 사용한다. `--*.id`는 해당 폴더의 파일 이름을 결정한다.

이전 시제품의 `so102 calibrate`로 만든 `calibration/{role}/*.json`은 자체 포맷이다. 파일을 그대로 LeRobot 캐시에 복사하지 말고 위 공식 명령으로 보정한다.

## 5. 카메라 없이 텔레오퍼레이션

두 암의 대응 관절 자세를 맞추고 작업 공간을 비운 뒤 실행한다. 카메라 설정 기본값은 비어 있다.

```bash
lerobot-teleoperate \
  --robot.type=so102_follower \
  --robot.port=/dev/so102_follower \
  --robot.id=so102_follower \
  --teleop.type=so102_leader \
  --teleop.port=/dev/so102_leader \
  --teleop.id=so102_leader \
  --display_data=false
```

요청 주기와 실행 시간을 제한하려면 다음 옵션을 위 명령에 추가한다.

```text
--fps=30
--teleop_time_s=10
```

`Ctrl+C`로 종료한다. 연결·모터 설정·토크 제어·종료는 공식 `SOFollower`와 `SOLeader`의 구현을 그대로 사용한다. 종료 시 기본 팔로워 설정은 토크 해제다. 암을 지지하고 전원 차단 방법을 확인한 상태에서 구동한다. 통신 단절 시 소프트웨어 명령만으로 정지나 토크 해제를 보장할 수는 없다.

## 6. 제어 옵션

| 옵션 | 기본값 / 설명 |
|---|---|
| `--robot.max_relative_target` | None, 공식 기본값. 지정하면 매 주기 현재 위치 대비 목표 차이 제한 |
| `--robot.use_degrees`, `--teleop.use_degrees` | true, 양쪽을 동일하게 설정 |
| `--robot.disable_torque_on_disconnect` | true, 종료 시 토크 해제 |
| `--robot.cameras` | `{}`, SOFollower의 표준 카메라 설정 전달 |

몸체 관절 단위는 deg, 그리퍼는 0~100이다. `use_degrees=false`이면 몸체는 -100~100 정규화 단위로 바뀐다.

SO-102 전용 초기 자세 검사나 별도 제어 제한을 추가하지 않는다. `get_action()`과 `send_action()`도 공식 구현을 그대로 상속한다. 현재 위치 대비 목표 차이를 제한하려면 공식 옵션인 `--robot.max_relative_target=2.0` 등을 명시한다. 이 값은 매 주기의 목표 차이이며 초당 속도나 전체 이동 각도 제한은 아니다.

제어 루프·주기·시각화 옵션은 LeRobot이 처리한다. 별도 `so102 teleoperate` 시제품 루프의 지연 감지 설정을 공식 CLI에 적용하지는 않는다. 녹화·학습·카메라의 실장비 연동은 이번 기본 텔레오퍼레이션 검증 범위 밖이다.

## SO-102 관절 구성

SO-102 플러그인의 설치 배포명과 모듈 이름은 `lerobot_robot_so102`다. 팔로워는 LeRobot의 기본 `SOFollower`, 리더는 기본 `SOLeader`를 확장한다.

| 모터 ID | 관절 | 기본 단위 |
|---|---|---|
| 1 | shoulder_pan | deg |
| 2 | shoulder_lift | deg |
| 3 | elbow_flex | deg |
| 4 | wrist_flex | deg |
| 5 | wrist_yaw | deg |
| 6 | wrist_roll | deg |
| 7 | gripper | 0~100 |

추가 축은 `wrist_yaw`이며 그리퍼까지 7개 `.pos` 특성을 제공한다. 실제 출고 모터 구성과 매핑은 장비에서 확인한다.

## 보조 도구

모델·원시 진단 도구는 별도로 남아 있다.

```bash
so102 model
so102 doctor
so102 diagnose --role leader
so102 diagnose --role follower
```

모터 ID가 초기 설정되지 않았다면 한 개씩 연결하여 아래 보조 명령을 사용한다.

```bash
so102 setup-motor --role follower --joint wrist_yaw --execute
```

LeRobot v0.6.0의 `lerobot-setup-motors`는 장치 화이트리스트와 자체 등록 방식 때문에 이 외부 타입을 자동 지원하지 않는다. 보조 명령은 기본 텔레오퍼레이션이나 보정에 필요하지 않다.
