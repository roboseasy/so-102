# 문제 해결

| 증상 | 확인 및 해결 |
|---|---|
| `so102_follower` / `so102_leader`가 unknown choice | 같은 Conda 환경에서 `python -m pip show lerobot_robot_so102` 확인 후 저장소에서 `python -m pip install -e .` |
| 공식 CLI 도움말에 SO-102가 없음 | `conda activate lerobot060` 후 아래 도움말 명령 실행. LeRobot 버전이 0.6.0인지 확인 |
| `lerobot-teleoperate` 명령 없음 | `conda activate lerobot060`, `python -m pip install -e .` |
| `lerobot060` 환경 없음 | `conda env create -f environment.yml` |
| Python 버전 오류 | `python --version`, `which python`으로 Python 3.12 환경 확인 |
| `/dev/so102_*`가 없음 | [포트 고정](<2. ports.md>) 적용 또는 명령에 실제 `/dev/ttyACM*` 지정 |
| 포트 권한 부족 | 아래 「시리얼 포트 Permission denied」 절차로 `dialout` 등록 및 현재 세션 반영 확인 |
| 모터 응답 없음 | 전원·케이블·7개 모터 ID 및 모델 확인 |
| 보정 파일이 다르거나 누락됨 | 올바른 포트·장치 ID·보정 경로를 확인하고 `lerobot-calibrate` 수행 |
| 이전 `so102 calibrate` 파일을 가져온 뒤 오류 | 자체 포맷 파일 대신 공식 calibrate 명령으로 보정 |
| 같은 자세에서 리더·팔로워 관절값이 다름 | 보정 범위·관절 대응·양쪽 `use_degrees` 설정 확인. 아래 보정 좌표 설명 참고 |
| 종료 시 팔이 내려옴 | 기본 토크 해제로 발생할 수 있음. 암을 지지한 상태로 종료 |
| `lerobot-setup-motors`에서 SO-102 미지원 | v0.6.0은 외부 타입을 자동 등록하지 않음. 필요한 경우 보조 `so102 setup-motor` 사용 |

```bash
conda activate lerobot060
python -m pip show lerobot lerobot_robot_so102
python -m pip check
lerobot-teleoperate --robot.type=so102_follower --teleop.type=so102_leader --help
```

LeRobot 설치가 소스 editable 방식이어도 사용할 수 있다. 설치된 메타데이터와 실제 소스 버전은 0.6.0이어야 한다.

보정 기본 위치는 `~/.cache/huggingface/lerobot/calibration/`이며, `HF_LEROBOT_HOME`, `HF_LEROBOT_CALIBRATION` 또는 `--*.calibration_dir`를 지정한 경우에는 그 경로를 확인한다.

## 같은 자세에서 리더·팔로워 관절값이 다른 경우

SO-102는 공식 `SOFollower`와 `SOLeader`의 보정·제어를 그대로 사용한다. 별도의 초기 자세 차이 검사는 없다.

LeRobot의 도 단위는 각 암에서 측정한 최소·최대 범위의 중간을 각각 0°로 삼으므로, 물리 자세가 같아도 수치가 달라질 수 있다. 리더·팔로워 포트와 보정 파일의 대응을 확인하고, 보정할 때 양쪽에서 대응하는 전체 운용 범위를 측정한다. `wrist_roll`은 공식 코드에서 별도로 0~4095 범위를 사용한다.

기본 `use_degrees=true`에서 몸체 관절은 도(°), 그리퍼는 0~100의 정규화 값이다. `use_degrees=false`이면 몸체도 -100~100의 정규화 값이며 양쪽 설정이 같아야 한다. 공식 옵션 `max_relative_target`의 기본값은 `None`이다. 이 옵션을 지정하더라도 영점 차이를 보정하지는 않는다.

## 시리얼 포트 Permission denied

`lerobot-calibrate` 또는 `lerobot-teleoperate` 실행 시 다음 오류가 나오면 시리얼 포트 접근 권한을 확인한다.

```text
PermissionError: [Errno 13] Permission denied: '/dev/ttyACM0'
```

`lerobot-find-port`로 포트를 찾았더라도 실제 통신 권한이 없으면 연결에 실패할 수 있다.

```bash
ls -l /dev/ttyACM*
id -nG
id -nG "$(whoami)"
```

포트가 `root dialout`, 권한이 `crw-rw----`라면 현재 세션에 `dialout` 그룹이 필요하다.
`id -nG`는 현재 세션, `id -nG "$(whoami)"`는 계정에 등록된 그룹을 보여 준다.

계정에도 `dialout`이 없을 때만 등록한다.

```bash
sudo usermod -aG dialout "$(whoami)"
```

이미 등록되어 있어도 현재 세션에 반영되지 않았다면 해당 터미널에서 다음을 실행한다.
`newgrp`는 새 셸을 열므로 Conda 환경도 다시 활성화한다.

```bash
newgrp dialout
conda activate lerobot060
id -nG
```

출력에 `dialout`이 포함되면 실제 리더 포트에 맞춰 보정을 다시 실행한다.

```bash
lerobot-calibrate \
  --teleop.type=so102_leader \
  --teleop.port=/dev/ttyACM0 \
  --teleop.id=so102_leader
```

전체 로그인 세션에 반영하려면 OS에서 로그아웃 후 다시 로그인하고 IDE/Codex도 다시 시작한다.
